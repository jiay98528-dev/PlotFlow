# 项目文档总索引

这是第一级索引。阅读顺序为“本页 → 对应分类索引 → 所需具体文档”，不要求每次任务通读整个文档库。

## 第二级分类

| 分类索引 | 查看时机 |
|---|---|
| [产品与品牌](indexes/product.md) | 了解项目、讨论需求、调整范围或品牌时 |
| [交互、主题与视觉](indexes/design.md) | 修改桌面交互、主题、品牌资产或官网设计时 |
| [故事数据与引擎](indexes/data.md) | 修改语法、数据结构、导出、节点身份或引擎接入时 |
| [工程规则与架构](indexes/engineering.md) | 开始实现、处理会话同步、改动工程配置或定位缺陷时 |
| [状态、验证与部署](indexes/delivery.md) | 询问进度、准备验证、构建软件、部署网站或反馈服务时 |

## 使用方式

- 新任务或上下文恢复先遵循 [AGENTS.md](../AGENTS.md)，再从本页选择分类。
- 每个分类表列出第三级文档、维护职责和具体查阅时机。只读取当前任务需要的条目；跨模块任务再扩展到另一分类。
- 查询状态进入“状态、验证与部署”，读取 progress.md；不要从旧提交、文件时间或历史测试数字推断当前状态。
- 新增、删除、改名或改变文档职责时同步所属分类；一份正文只归入一个主分类，跨领域通过正文链接互相引用。

## 覆盖边界

三层结构覆盖当前仓库中全部自有 Markdown 文档，包括项目规则、规格、README、决策和维护说明。本页及 doc/indexes 为索引层，其余为正文层；不另建第四层导航。

源代码中的 API 注释、机器 Schema/JSON 案例、故事 fixtures、视觉回归快照和品牌源图保留在各自维护目录，由第三级文档链接到真实来源，不复制成第二份人工文档。

第三方依赖、Git 对象、本地配置、构建目录、运行日志和 release 内生成的交付说明不属于源码文档库。当前开发交付入口为 release/baseline/README.md，包内源码包含同一套文档索引。历史报告、调研快照、任务提示词与未采用草稿从 Git 历史查询。
