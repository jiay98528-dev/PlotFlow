# Fablevia（维叙）官网落地页设计基线

> 建立日期：2026-08-12  
> 适用范围：`website/` 官网首页、后续产品介绍页与转化路径  
> 当前阶段：设计基线，不包含页面实现  
> 关系说明：本文不覆盖 `spec/design-brief-editor-ux.md`，后者仍是桌面编辑器 UI/UX 的唯一真相源。

## 1. 基线结论

官网首页应从现有的“项目说明与开发状态入口”转为“面向独立游戏团队的产品解释与转化页面”。访客首先需要理解维叙解决什么问题、工作流为何可信、自己的故事数据是否安全，最后才需要看到版本状态、技术细节和主题目录。

推荐冻结的核心表达：

- 品类：本地优先的叙事分支工作台。
- 核心承诺：把分支故事画清楚，再把干净数据交给引擎。
- 机制解释：默认在 Graph Lab 用画布与 Inspector 创作，同时把全部故事可靠保存为开放的 `.mdstory` 纯文本。
- 主要受众：1 到 5 人独立游戏团队中的独立开发者与叙事设计师。
- 核心差异：图形化创作与可读源码不是两套系统，而是同一故事文件的双投影。
- 品牌性格：安静、精密、生长。
- 官网视觉方向：原生创作工作台与有生命的分支系统，不复制某一套应用主题，也不采用纸媒杂志式科技落地页。

推荐首页首屏文案：

```text
本地优先的叙事分支工作台

把分支故事画清楚，
再把干净数据交给引擎。

维叙（Fablevia）让独立游戏团队直接在 Graph Lab 编排节点、条件与变量，
并把全部内容可靠保存为开放的 .mdstory 纯文本。
```

## 2. 事实来源与使用优先级

官网公开主张按以下顺序取证，较低层资料与较高层冲突时不得直接采用：

1. `doc/adr/ADR-015-fablevia-brand.md`：对外品牌与兼容命名空间。
2. 根 `package.json`、`packages/app/src/shared/productIdentity.ts`：当前版本、发布通道和产品名。
3. `spec/progress.md`、`spec/release-blackbox-gate.md`：当前源码与发行状态。
4. `PRODUCT.md`、`DESIGN.md`：用户、品牌性格和产品设计原则。
5. 当前产品源码、测试、打包配置与真实截图：实际可用能力。
6. `PRD.md`、`spec/design-brief-editor-ux.md`：产品合同与交互规格。
7. `COMPETITIVE_ANALYSIS.md`、`STATUS_AND_POTENTIAL.md`：历史定位研究，只能作为假设来源。竞品价格、市场数字和比较结论在公开前必须重新核验。
8. 当前 `website/src/data/siteContent.ts` 与 `website/public/data/project-status.json`：早期官网内容，不是更高层事实来源。

当前官网状态数据生成于 2026-07-11，早于 `spec/progress.md` 的 2026-08-10 源码快照，不能继续作为首页实时状态主张。

## 3. 已确认的产品事实

| 领域 | 当前可确认事实 | 官网使用方式 |
|---|---|---|
| 对外品牌 | 中文以“维叙”为主名，小字辅助 `Fablevia`；英文只显示 `Fablevia` | 全部用户可见页面遵循该锁定方式 |
| 技术旧名 | `plotflow` 只保留在 Schema、包名、API、主题 ID、IPC、本地目录等兼容标识 | 普通营销页面不出现，开发文档可解释一次 |
| 产品品类 | 面向独立游戏团队的本地优先叙事分支编辑器 | 首屏直接说明，不使用泛化“创意平台” |
| 默认工作区 | Graph Lab 是首次启动、新建、打开和继续编辑的主要且默认工作区 | 真实产品截图以 Graph Lab 为主角 |
| 数据真相源 | `.mdstory` 是唯一磁盘真相源，GUI 与源码编辑写回同一文件 | 作为第二核心价值，与图优先并列 |
| 源码投影 | Split 在顶栏并列保留，Source Drawer 提供当前章节源码切片 | 用来证明透明、可恢复和 Git 友好 |
| 图形编辑 | 支持章节、节点、正文、选项、条件、效果、变量、连线和布局的 GUI 编辑 | 通过一个连续故事演示，不拆成大量同形功能卡 |
| 诊断 | 当前合同包含 8 类错误、7 类警告、3 类建议，错误会阻断导出 | 表达为“在交给引擎前发现断链与变量问题” |
| 导出 | JSON Schema 0.2、单文件可玩 HTML、纯文本 TXT | 以程序交接、试玩、校对三个结果说明价值 |
| 补全 | 本地 N-gram 四维补全、增量学习与语料导入已实现 | 称为“本地统计补全”，不包装成云端 AI |
| 模板 | 空白模板加 RPG 对话、视觉小说、解谜逃脱、Godot 示例 | 可作为上手速度证据，不将空白模板计入“四个场景模板” |
| 主题 | 当前 0.1.1 编译内置 Prism Foundry、Narrative Workbench、Engine Telemetry 三套官方主题 | 放在产品深度展示后，不作为首要购买理由 |
| 语言 | 桌面主路径覆盖简体中文与英文 | 中文官网默认中文，英文内容独立可索引 |
| 引擎 | Godot 编辑器插件与运行时已实现；Unity 有读取接口与参考实现但示例场景延后；Unreal 为数据与 Blueprint 合同 | 首页主打 Godot；Unity、Unreal 必须带能力层级限定 |
| 当前版本 | 根包为 `0.1.1`，发布通道为 `preview` | 未进入稳定公开发行前使用“Windows 预览版”口径 |
| 当前平台 | Windows 已存在安装包与候选产物；macOS/Linux 打包与冒烟任务延后 | 不写“三平台现已可用” |
| 当前商业模式 | README 与 PRD 记录 `$29` 买断策略，仓库没有真实结账、授权、退款和公开下载路径 | 可作为待确认商业口径，不能先做虚假购买按钮 |
| 许可证 | 根包声明 `Proprietary`，但仓库没有可公开链接的 `LICENSE` 文档 | 正式销售前补齐许可说明，不沿用 README 中的失效链接 |
| 联网边界 | 故事编辑、补全、解析和导出以本地为主；应用内 BUG 反馈会向维护者发送邮件 | 不使用“绝不联网”绝对表述，改为“核心创作无需联网，故事与学习数据留在本地” |

## 4. 受众与转化优先级

### 4.1 第一优先：独立游戏开发者与小团队主创

- 情境：同一个人或小团队同时承担叙事、设计和实现，工具切换成本高。
- 当前做法：用思维导图、表格、Markdown、引擎脚本和手工 JSON 拼接工作流。
- 核心焦虑：分支一多就看不清；条件和变量容易出错；文案交给程序时需要二次翻译；云端或专有格式让数据失去控制。
- 期望结果：在一个本地工作台中画清结构、直接编辑内容、提前发现问题，并产出引擎能消费的数据。
- 最强证据：Graph Lab、`.mdstory`、实时诊断、JSON/HTML/TXT、Godot 闭环。
- 常见疑问：是否必须学语法、是否会锁格式、能否接入自己的引擎、是否只适合视觉小说。

### 4.2 第二优先：叙事设计师与文案策划

- 情境：熟悉故事结构，不一定熟悉脚本语言。
- 核心焦虑：必须记语法才能表达条件；大型分支靠脑补；修改后不知道哪些路径断了。
- 期望结果：以画布、Inspector 和章节导航为主完成创作，需要时才查看源码。
- 最强证据：完全 GUI 的核心闭环、字段化条件和效果、节点诊断、Source Drawer。

### 4.3 第三优先：程序与引擎集成者

- 情境：不负责写文案，但要把叙事可靠接入游戏。
- 核心焦虑：格式随作者习惯漂移；变量类型不稳定；每次改稿都要手工转换。
- 期望结果：拿到稳定 Schema、可验证 JSON 和明确的运行时合同。
- 最强证据：JSON Schema 0.2、错误阻断导出、Godot 运行时、Unity 读取参考、开放纯文本源。

### 4.4 次要人群

游戏设计院校师生、视觉小说与互动小说制作者适合进入案例或 FAQ，不应在首屏与前三类角色平分权重。桌游剧本作者目前只是潜在扩展场景，不作为首页承诺。

## 5. 定位与信息层级

### 5.1 定位句

```text
维叙是面向独立游戏团队的本地叙事分支工作台。
它让用户默认在 Graph Lab 用画布完成创作，同时把全部内容保存为可读、可追踪、可交接的 .mdstory 纯文本。
```

### 5.2 首页信息优先级

1. 看清并直接编辑故事结构。
2. 保有自己的故事数据，不被专有格式和云端绑定。
3. 在交接前发现断链、死胡同和变量问题。
4. 一次创作，产出 JSON、HTML 和 TXT。
5. 用本地补全、模板、主题和中英双语提升日常效率。

### 5.3 差异化表达

| 市场张力 | 维叙的回答 | 推荐说法 |
|---|---|---|
| 图形工具直观，但常把数据锁进专有项目 | 图形编辑写回 `.mdstory` | “画布是工作方式，纯文本是你的数据。” |
| 脚本工具开放，但非程序用户学习成本高 | Graph Lab 默认，Split 随时可用 | “先在画布上创作，需要时再深入源码。” |
| 文案和程序之间需要手工翻译 | 诊断、Schema 与多格式导出形成交接闭环 | “故事写完，交付文件也准备好了。” |
| 云端协作工具依赖账号和网络 | 核心创作与补全本地运行 | “没有网络，也能继续写、检查和导出。” |
| 中文叙事工具常是翻译后的第二语言体验 | 中文为默认主路径，英文完整覆盖 | “从界面到诊断，都为中文创作完整设计。” |

### 5.4 不应作为首页主叙事的内容

- Electron、React、Monaco、React Flow、Dagre 等技术栈。
- 132/142、测试文件数量、门禁名称和哈希。
- 三套主题的完整架构与安全实现。
- 远期云同步、GPT、主题市场和 Unreal 完整运行时。
- 未经重新核验的竞品价格、市场规模、节省百分比和“唯一蓝海”结论。
- “AI 写作神器”“全平台”“正式发布”“发行候选已通过”等当前证据不支持的词。

## 6. 转化目标与行动按钮

当前仓库没有已经确认的公开购买与下载路径，首页不得使用 `href="#"`、无法完成的“立即购买”或伪下载按钮。页面实现前需要根据发行阶段选择一种转化模式。

| 模式 | 适用条件 | 主行动 | 次行动 |
|---|---|---|---|
| 预发布说明 | 公开下载路径尚未准备好 | 查看产品演示 | 阅读使用说明 |
| Windows 预览 | 有可公开下载、版本说明和风险说明 | 获取 Windows 预览版 | 查看工作流 |
| 正式销售 | 结账、授权、下载、退款和签名口径全部明确 | 获取 Windows 版，`$29` 买断 | 先看产品演示 |

无论采用哪种模式，主行动在桌面导航、首屏和页尾保持同一动词。开发进度可保留为页尾信任入口，不再与主行动并列竞争。

推荐导航：

```text
产品  工作流  引擎接入  定价或预览  使用说明  中文/English  主行动
```

## 7. 推荐页面叙事

| 顺序 | 访客问题 | 内容与证据 | 版式方向 |
|---|---|---|---|
| 1. 首屏 | 这是什么，是否适合我？ | 核心承诺、目标人群、当前平台口径、真实 Graph Lab 画面 | 左侧强文案，右侧或下方大幅真实产品窗口；不使用抽象白板替代截图 |
| 2. 工作流冲突 | 它替我省掉什么？ | 从“脑补分支、手工翻译”到“画布创作、诊断、导出” | 用一条连续的故事分支穿过页面，不做四张同形痛点卡 |
| 3. 双投影 | 图形化会不会锁数据？ | 同一节点在 Graph Lab、Source Drawer、`.mdstory` 中的对应关系 | 用精确映射或滑动切换展示同一数据的不同投影 |
| 4. 创作闭环 | 实际怎么写？ | 创建节点、连接路线、编辑条件和变量、查看诊断 | 以一个 RPG 或视觉小说片段连续演示，避免功能碎片化 |
| 5. 程序交接 | 最后能给引擎什么？ | JSON Schema 0.2、HTML 试玩、TXT 校对、Godot | 从一个 `.mdstory` 分流到三个结果，Godot 作为主集成证据 |
| 6. 数据与隐私 | 我的内容在哪里？ | 本地文件、Git 友好、本地统计补全、无强制账号 | 直接展示文件和目录事实，不用泛化盾牌图标堆砌 |
| 7. 适用场景 | 它适合哪类项目？ | Game Jam、RPG 对话、视觉小说、解谜叙事 | 用现有模板内容做真实微案例 |
| 8. 个性化 | 长时间使用是否舒服？ | 三套内置主题与中英双语 | 使用真实主题截图，压低层级，不设外部主题商店主按钮 |
| 9. 价格或预览 | 现在如何开始？ | 当前版本、Windows、买断或预览条件、包含内容 | 单一清晰方案；不做虚构套餐比较 |
| 10. FAQ 与页尾 | 还有哪些边界？ | 是否联网、是否支持协作、平台、引擎、文件格式、升级 | 诚实说明非实时协作、非项目管理、非游戏逻辑引擎 |

## 8. 视觉设计基线

### 8.1 使用场景

一名独立游戏开发者在白天的自然光工作室里，用 27 英寸显示器连续梳理几十条剧情分支，并准备把当天的改稿交给 Godot。页面应支持长时间阅读，默认采用明亮基底，同时通过结构色与真实产品画面建立能力感。

### 8.2 品牌语汇

- 安静：不过度喊叫，不用霓虹噪声和密集动效制造“专业”。
- 精密：层级、对齐、线缆、字段和状态都像可靠的原生工具。
- 生长：节点不是冷冰冰的流程块，故事从一页文本长成可探索的分支。

建议美学名称：`Living Workbench`，中文可称“生长中的叙事工作台”。它不是游戏 HUD，不是纸媒杂志，也不是常见的紫色 SaaS 卡片页。

### 8.3 颜色策略

采用 Committed 策略。品牌蓝承担首屏、导航关键状态、分支线和主行动，约占主要视域的 30% 到 45%；暖白提供叙事呼吸感；珊瑚、叶绿和信号青只用于路径节点和语义提示。

建议官网 token 起点：

| 角色 | 建议值 | 来源与用途 |
|---|---|---|
| `brand-cobalt` | `oklch(0.56 0.18 260)` | 现有图标主蓝，主行动与结构背景 |
| `brand-cobalt-deep` | `oklch(0.43 0.16 260)` | 深色文字反差、首屏深面 |
| `canvas-ivory` | `oklch(0.98 0.018 80)` | 图标纸张色，正文与长阅读背景 |
| `canvas-cool` | `oklch(0.96 0.025 265)` | 与 Prism Foundry 产品画布衔接 |
| `ink` | `oklch(0.24 0.025 260)` | 主要文字，不使用纯黑 |
| `signal-cyan` | `oklch(0.64 0.13 210)` | Graph Lab 连线与交互证据 |
| `story-coral` | `oklch(0.72 0.15 31)` | 关键分支节点与提示，低频使用 |
| `story-leaf` | `oklch(0.76 0.11 155)` | 成功、完成和生长意象，低频使用 |

所有实现颜色进入 CSS Design Token。组件中不写裸色值，不以颜色作为状态的唯一表达。

### 8.4 字体

当前官网使用 Iowan Old Style、Source Serif Pro 与 IBM Plex Mono，形成明显的编辑杂志风，与产品的原生工作台定位和新的品牌基线不一致。新官网不沿用这套组合。

字体方向：

- 主体使用一套有中文质量、拉丁数字清晰、适合工具品牌的 committed sans。
- 标题通过字号、字重与紧缩字距建立个性，不默认叠加展示衬线。
- `.mdstory`、JSON 与快捷键可以使用等宽字体，等宽字体不承担品牌主标题。
- 正文单行控制在 65 到 75 个字符，中文段落使用舒适行高。
- 最终字体家族需在页面 shape 阶段从真实字体目录选择并核验 Web 许可、中文覆盖与加载体积，本基线不虚构未验证的品牌字体。

### 8.5 布局与形态

- 首屏采用不对称构图，让真实产品窗口跨出常规内容列，避免居中图标、标题、副标题、双按钮的模板结构。
- 桌面使用明确的 12 列网格，但分支线可以跨越网格连接前后章节。
- 节奏使用“短解释、长产品画面、短结论”的变化，不给每个模块相同内边距。
- 卡片只用于确实独立的对象，如主题、价格方案和 FAQ；不将全部功能装进相同图标卡。
- 圆角继承软件图标和原生窗口的克制形态，不把所有表面做成大圆角胶囊。
- 玻璃材质只在产品窗口或导航层级有真实空间意义时使用，不作为默认装饰。
- 禁止渐变文字、彩色侧边条、嵌套卡片和大数字进度模板。

### 8.6 动效

- 首屏只需要一次编排清晰的进入动效，重点是分支线从文稿生长到节点图。
- 产品演示使用真实操作序列：创建节点、拖线、诊断出现、导出完成。
- 动画只使用 `transform`、`opacity` 和路径绘制等低成本属性，不动画布局属性。
- 使用 ease-out quart、quint 或 expo，不使用弹跳与弹性效果。
- 完整支持 `prefers-reduced-motion`，减弱模式保留最终状态和信息顺序。

### 8.7 响应式与可达性

- 1440px 桌面：完整首屏产品窗口与长横向工作流。
- 1024px 窄笔记本：产品窗口保持可读，文字和截图改为上下关系。
- 390px 手机：导航折叠；首屏只保留一个主行动；产品画面使用有意义的局部裁切或纵向演示，不能简单把 1440px 界面缩成不可读缩略图。
- 所有交互具备键盘路径、可见 `focus-visible`、可访问名称与至少 WCAG AA 的普通文本对比度。
- 截图有描述性替代文本；装饰性分支线从辅助技术隐藏。
- 中英切换不能依赖仅图标提示。

## 12. 官网技术与内容基线

- 继续使用独立 `website/` React/Vite 项目，不并入桌面应用包。
- 首页营销内容与开发状态数据解耦，首页不读取内部里程碑数字。
- 中文和英文使用独立、可索引的 URL，而不是只靠客户端状态切换。
- 每种语言拥有独立的 `<title>`、description、Open Graph、canonical 和 `hreflang`。
- 只有在平台、价格与下载路径确认后才输出 `SoftwareApplication` 与 `Offer` 结构化数据。
- 产品截图优先输出 AVIF/WebP，并保留 PNG 回退；首屏只预加载真正的 LCP 图。
- 核心内容在 JavaScript 失败时仍应可读，后续实现可选择静态生成或预渲染。
- 不引入数据库、CMS、账号系统或分析工具作为落地页的默认前提。
- 如后续接入分析或邮件收集，必须先确定隐私说明与数据最小化范围。
