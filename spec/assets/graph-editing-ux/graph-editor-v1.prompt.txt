Use case: ui-mockup
Create one polished high-fidelity desktop application UX mockup for Fablevia (维叙), an offline branching-story editor for Chinese narrative writers. This is a proposed redesigned product interface, not a marketing poster or a technical diagram. Render a razor-sharp straight-on flat screenshot, wide 16:10 landscape, preferably 2560×1600 or higher, filling the image edge to edge. Carefully typeset readable simplified Chinese. No mock laptop, no perspective, no surrounding presentation board, no annotations outside the interface.

Visual direction: elegant professional native desktop creative tool, pearl cool-white panels, extremely subtle lavender-tinted canvas, fine neutral separators, restrained violet selection and primary action, thin gray curved graph connections, subtle depth, high contrast dark text. Dense enough for serious writing but spacious readable controls. 8–10px corner radius, consistent delicate line icons, sophisticated typography. Quiet and precise. Not a generic dashboard, no gradients across panels, no glowing edges, no bright colored cards, no giant headers. Windows titlebar controls. Brand upper left text “维叙” with smaller “Fablevia”; do not invent an elaborate new logo.

Layout: real three-column application. Thin 56px top app bar, 44px chapter tabs below, left 220px story navigation, large center branching canvas roughly 60% of remaining area, right 440px editing panel around 30%. Bottom 26px discreet status bar. Main primary workspace title “剧情图”, adjacent secondary mode “源码”. File “雾镇来信.mdstory”; top search “搜索剧情…”; minimal undo, redo icons and buttons “保存”, “导出”. Second navigation row chapters “第一章 · 雾镇” selected, “第二章 · 山路”, plus add chapter. Avoid all old terms Graph Lab, Inspector, Source Drawer, Frontmatter, AST, int, bool, AND, OR, effects, schema, debug.

LEFT panel: top section “剧情目录”, small + action. Chapter “第一章 · 雾镇”. Indented story entries “镇口”, “药店” (selected lavender highlight), “获得药水”, “暂时离开”. Secondary section “故事设置” with “故事信息” and “变量” (small count 2). At bottom a compact variables summary: “金币” and “拥有药水”. Creation button “＋ 新建剧情” separated from canvas layout controls. No elaborate type forms in navigation.

CENTER CANVAS: faint small dot grid, large readable story node cards with proper visible connection sockets and gentle orthogonal/bezier links that do not cross text. Layout is left-to-right: “镇口” upstream on left, selected “药店” in center, two outcomes “获得药水” upper right and “暂时离开” lower right, allowing partial landscape use but all cards fully visible and no overlaps. Cards have title, short text, compact choice rows with readable route summaries, not large colorful chips. Node “镇口”: “薄雾中，药店亮着一盏灯。” one row “走进药店”. Selected “药店” violet outline: body “店主递来一瓶药水，售价十枚金币。” row 1 “购买药水” secondary “金币不少于 10 · 金币 −10”; row 2 “暂时离开” secondary “不限条件”. Output sockets align with their individual route rows and connect to matching destination cards. “获得药水” body “你收好药水，继续赶路。” and “暂时离开” body “你决定先去别处看看。” Use route direction arrows. Node sizes visually coherent, not stretched full-height. Canvas bottom-left tiny controls “−   100%   ＋” and “整理布局”; tiny minimap optional, no huge HUD.

RIGHT PANEL is the key focal area: heading “剧情详情”, current node title field “药店”, visible short body textarea “店主递来一瓶药水，售价十枚金币。” Thin separators, no card within card within card.
Then section “玩家选项” with a small “＋ 添加选项”.
Expanded selected option “购买药水” with subdued chevron and overflow menu. Labeled destination “前往” and dropdown “获得药水”.
Subsection “选择条件”, single natural-language horizontal or neatly wrapped row with actual pill-like form controls: variable dropdown “金币”, relation dropdown “不少于”, numeric input “10”. Underneath small actions “＋ 添加条件” and subdued “高级条件”. No logic tree, no operand-source selectors for this simple case.
Subsection “选择后发生的变化”: two editable rows with clear visual hierarchy:
row one variable dropdown “金币”, action dropdown “减少”, value input “10”, small remove icon.
row two variable dropdown “拥有药水”, action dropdown “设为”, boolean dropdown “是”, small remove icon.
Each row must fit the panel with sensible wrapping if needed. Use familiar narrative language, never programming booleans. Small actions underneath “＋ 添加变化” and “＋ 新建变量”. A subtle readable summary line “扣除 10 金币，并获得药水。” This explains a rule, not a live simulation or runtime balance; do not claim actual current inventory values.
Then compact collapsed second option “暂时离开” with small “不限条件 · 无变化”, chevron. Bottom of panel can have subtle “章节源码” advanced link, not expanded source content.

Status bar says “已保存” and “4 段剧情 · 2 个选项”.
Keep Chinese exactly as specified wherever possible. Ensure no clipping, overlapping text, phantom drag handles, invalid numeric operations, formula fields, source code, or developer terminology. Feature grouping must express writing, choice requirements, and consequences. This is a realistic implementable static mockup of the existing graph editor redesign, not an invented new product with extra features.
